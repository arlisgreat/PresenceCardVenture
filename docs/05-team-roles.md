# MVP 分工（简版）

更新：2026-08-27。本文作为当前阶段的分工基准，旧规划中不一致的角色安排与批量发机计划不适用。

## 当前目标

1 张 M5Stack CoreS3 Lite 展示小卡，至少 200 位用户可扫码加入 Web 社区，无需持有硬件。核心是**小卡与云端双向同步、好友 AI 图像共创、Web 文字/图片交流**；语音和离线近场卡间互动留待后续。200 用户的并发场景由全栈压测确认。

## 角色与交付

| 角色 | 主责 | 交付物 |
|------|------|--------|
| 全栈工程师 | Web 社区、登录/好友/聊天、共创界面、业务 API、设备绑定与双向同步；阿里云服务器、域名/HTTPS、数据库、OSS、部署与监控 | 可访问的 Web/API、开发与生产环境、联调账号、日志和压测结果 |
| 硬件工程师 | CoreS3 Lite 拍照与 JPEG 编码、滤镜接入、屏幕交互、Wi-Fi、上传/下载/展示回执、断网补传与功耗；3D 外壳与整机 | 可烧录固件、烧录说明、串口日志、真机视频和外壳文件 |
| 算法 | 原创 Dazz 类滤镜、效果参数、image API 适配与 AI 合照流程、模型配置；质量/延迟/成本评测及跨端技术协调 | 滤镜参数包、输入/输出效果样例、可调用的图像处理模块或服务、评测结果 |
| UI 设计 | 手机 Web 社区与 320×240 小卡屏幕设计、视觉规范、滤镜目标效果、交互/加载/失败状态 | Figma 页面与组件、设备屏稿、滤镜参考图及视觉验收 |
| CEO | 产品范围与优先级、预算、社区及隐私规则、测试用户组织、最终产品验收与发布决策 | 确认的 MVP 清单、预算/额度、内测名单和发布标准 |

## 协作边界

- 算法提供效果实现与参数，UI 确认视觉，硬件负责端侧适配，全栈负责云端部署及 Web/业务接入；不重复建设两套后端。
- 全栈与硬件直接按 `main` 中的 [设备规范](02-device-api-v1.md) 和 [OpenAPI](03-device-api.openapi.yaml) 联调；协议变更先 PR，双方确认后合并。
- 每项任务在 GitHub Issue 指定一个主负责人；完成时提交代码及截图、日志或真机视频，由对应技术/视觉负责人验收。

## 共同验收

首个技术闭环：**小卡拍照 → 上传 → Web 可见 → Web 选图下发 → 同一张小卡显示并回执**。

完整展示：**朋友扫码加入（不绑定展示设备）→ 加好友、发文字/图片 → 双方授权素材并生成 AI 合照 → 结果进入会话 → 经设备主人确认后发送到小卡**。
