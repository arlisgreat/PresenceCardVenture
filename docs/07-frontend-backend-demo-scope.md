# 完整社区应用与 Demo 交付范围

## 目标

在不依赖真实硬件的前提下，交付一个可以真实操作的社区应用版本，覆盖“用户上传照片 → 云端处理 → 圈子展示与互动 → 可选生成合照 → 设备模拟联动”的端到端体验。真实硬件和第三方服务通过适配层接入，不阻塞应用交付。

## 第一阶段范围

### P0：必须可演示

- Web 用户身份：注册/登录或可替代的 Demo 用户身份。
- 图片上传：上传图片、保留原图元数据，并展示处理状态。
- 基础处理：至少支持一组 CCD/暖色等风格和基础美颜参数（匀肤、美白、清晰、大眼可先做可控的 Demo 效果）。
- 社区时间线：展示自己和已授权好友的图片，包含作者、时间、滤镜信息和图片预览。
- 互动：图片点赞，以及文字/图片消息的最小闭环。
- 删除：用户可以删除自己的原图、处理结果和 AI 合照结果。

### P1：完整应用必须可走通

- 贴纸或拍立得风格边框素材，先提供 1–2 个可用样式。
- AI 合照异步任务：创建任务、显示排队/处理中/成功/失败状态；Demo 阶段可使用模拟生成器。
- 设备模拟面板：模拟设备上传一张照片、拉取好友动态、接收下发并回传回执。
- 小圈、大圈和分圈筛选；默认采用授权可见，未授权内容不可进入时间线。
- 我的足迹：按日期查看自己发布过的照片与处理结果。
- 玩法库：轻美颜、CCD 滤镜、素材模板三类入口，选中配置后可标记为设备下发配置。
- 语音贴/一句话先提供文字状态和音频占位，真实 ASR 通过服务端适配器接入。

## 生产前置条件与明确限制

- 真实 M5Stack/CoreS3 硬件联调、拍照、刷屏和低功耗实现。
- 生产环境的 OSS、域名、HTTPS、限流、备份和压测需要部署环境凭据；代码和配置模板会准备好，但本地无法替代真实云资源。
- TikTok/抖音等第三方特效资源的正式接入，除非完成授权和资源确认。
- 语音、卡间离线互动以及离线好友票等协议中的预留能力。

## 验收标准

1. 用户可以在 Web 端完成一次图片上传，并看到原图和处理结果的关联关系。
2. 已授权好友可以在时间线看到图片；未授权用户看不到受限内容。
3. 用户可以对图片点赞、发送文字或图片消息，并删除自己拥有的内容。
4. 创建 AI 合照后，页面能展示任务状态；成功和失败都有明确反馈。
5. 设备模拟面板能完成上传、拉取和回执流程，且不改变设备 API 的字段语义。
6. API 和 Web 均能在本地按仓库 README 的方式启动，关键流程有可重复的测试或请求样例。

## 建议实现顺序

1. 先补齐 API 的健康检查、Demo 用户、图片元数据和本地文件存储。
2. 再实现 Web 上传、时间线和删除流程。
3. 加入滤镜/美颜处理适配层，先用本地可替换实现，保留算法服务接口。
4. 实现好友/可见范围和消息互动。
5. 接入 AI 合照任务状态机与设备模拟面板。
6. 最后按联调验收文档补请求样例、测试证据和已知限制。

## 已验证的闭环

- 模板创作：上传图片后选择“窗台手账”模板，可叠加星星贴纸或日期戳；发布后元数据会随 Feed 返回。
- 轻信号图片消息：添加图片会先通过 `/v1/photos` 上传，再通过 `/v1/messages` 携带 `photo_id` 发送；会话中直接展示图片。
- 浏览器验收：桌面 1280px、移动 375px 均无横向溢出；模板和图片消息流程无控制台错误，相关请求返回 2xx/201。
- 好友请求：轻信号页支持输入 6 位 `friend_code` 发起请求，收件人可接受；设备状态会返回真实的待处理请求数。
- 设备上传限额：API 按“作者 + 设备 + UTC 日期”计数，默认每日 60 张，可由 `UPLOAD_DAILY_LIMIT` 调整；重复 `Idempotency-Key` 不重复计数，超限返回 `429` 和 `retry_after`。
- 照片访问安全：二进制下载需要认证并再次检查自己/好友可见性；Web 使用受保护图片加载器携带认证头，非法文案、尺寸和美颜参数返回 `400`。
- AI 适配边界：`AiProvider` 接口支持注入真实模型服务；Demo 默认使用命名为 `simulator` 的可重复 provider，成功/失败状态和 provider 名称都会返回给客户端。
- AI 错误边界：Web 仅在网络不可达时使用本地模拟排队/结果；API 的鉴权、素材授权、限流、模型或存储错误会进入“生成失败”状态并提供重试，不会伪装成成功。
- AI 合照发布：任务完成后，主人可调用 `/ai/jobs/:id/publish` 将结果复制为自己的社区照片；首次发布返回 `201`，重复点击返回同一照片 `200`，任务未完成或非主人请求会被拒绝。
- 图片存储边界：`PhotoStorage` 的 `save/read/remove` 接口支持注入 OSS 等对象存储；Demo 默认使用本地 `PhotoStore`，上传、鉴权下载和删除流程保持相同契约。
- 存储故障保护：文件保存失败返回 `503 STORAGE_UNAVAILABLE`，不会把未落盘照片写入 Feed；客户端可用原幂等键重试。
- 下载或删除存储失败同样返回 `503`；删除失败时保留元数据，避免对象仍存在但所有者失去管理入口。
- Web 发布错误边界：只有网络不可达时才使用本地 Demo fallback；API 的鉴权、限流、参数或存储错误会保留服务端错误并解除 busy 状态，避免把失败伪装成已发布。
- Web 发布处理：浏览器在上传前使用 Canvas 将 JPG/PNG 缩放到最长边 1600px，并把选中的 CCD/暖色/鲜明/黑白滤镜、美颜亮度和星星/日期贴纸烘焙到 JPEG；API 接收处理后的实际宽高，同时继续保存处理结果元数据。浏览器不支持 Canvas 解码时保留原文件作为兼容降级。
- 会话隔离：`GET /v1/conversations/:id/messages` 只返回该会话双方的消息；无权或不存在的会话返回 `404`，不会泄露其他好友内容。
- 设备配对安全：配对码使用密码学随机的 6 位数字，并避免与当前未过期设备码重复；示例中的 `482913` 不会作为固定值返回。
- 设备模拟器联调：Web 绑定配对码后会查询 `/pair/status` 取得设备 token，并真实调用 `/device/heartbeat`；“拉取圈子”使用设备 token 请求 `/feed?limit=8`，保存 ETag 并在后续请求带 `If-None-Match`，命中 `304` 时保留当前预览；有新内容时更新最新照片并记录返回条数；“回执轻信号”使用设备 token 调用 `/device/ack`。未绑定时不会伪造成功回执。
- 玩法配置下发：玩法库选择会保存当前配置；绑定设备后，Device Lab 的“下发玩法”调用 `/device/config` 排队配置，并用 device token 读取 `/device/state` 确认 `pending_config`；小卡应用后以 `config_id` 回执确认。请求带幂等键，网络重试不会重复排队。
- 设备配置状态展示：Web 将待回执配置与已生效配置分开维护；回执后配置转为 active 并持续显示在设备屏幕和信息栏，后续再次下发只替换 pending，不会把已生效玩法错误重置为“原色”。
- 设备配置恢复：`GET /device/state` 同时返回 `pending_config` 与最近一次成功回执的 `active_config`；Web 重新绑定设备时恢复这两个状态，刷新或重连后仍显示真实生效玩法。
- 配对码续期：重复领取配对码只更新短期配对凭证，不覆盖设备绑定、心跳和已生效玩法状态，避免重连流程造成配置丢失。
- Web 设备会话：绑定成功后 Demo 在浏览器本地保存设备 token；设备页重新打开时先向服务端校验 token 并恢复 `active_config`/`pending_config`，失效 token 会自动清理。
- 设备状态统计：设备 token 读取 `/device/state` 时，未看动态和待处理好友数会按绑定账号的授权可见范围计算，不泄露全局计数。
- 设备拍照模拟：Device Lab 的“拍照并上传”会用内置 JPEG 帧调用 `/photos`，带上设备 token、`X-Device-ID` 和幂等键；返回的照片会立即显示在设备屏幕预览中。真实相机帧仍由 ESP32 固件替换。
- Feed 分页边界：`GET /feed` 和 `GET /photos/mine` 对 `limit` 强制使用正整数，超过 32 时按 32 返回，非法值返回 `400 BAD_REQUEST`，避免设备和 Web 获得不确定页大小。
- 分圈发布：释放页可选择小圈、傍晚的天空、胶片味或宿舍窗台；选择通过 `X-Circle` 写入照片元数据，Feed/足迹沿用该圈子筛选，网络不可达的本地 Demo fallback 也保留所选圈子。
- 圈子筛选：Feed 默认显示“全部”，切换到命名圈子后只显示该圈子的内容，并根据当前 Feed 动态显示各圈数量；“小圈”不再隐式混入其他圈子。
- 种子内容质量：Demo 初始 Feed 使用中文产品文案，并为每条内容提供真实的 `play_type`、`beauty`、`sticker` 元数据，避免工程占位文案出现在演示界面。
- 最新浏览器验收：API 重载后桌面 1440px 与移动 390px 均显示中文种子内容；移动端进入“合照”页可正常看到素材选择和生成入口，横向溢出为 0，控制台无新增错误。
- 社区邀请入口：`GET /v1/me` 返回当前账号的 `friend_code`；轻信号页使用本地 `qrcode` 库渲染可扫描二维码并提供可复制邀请链接，打开 `/?join=xxxxxx` 会自动进入好友请求视图并预填 6 位好友码，扫码和普通分享共用同一好友授权流程。
- 互动失败回滚：点赞采用受保护的乐观更新；服务端拒绝或网络失败时恢复原计数与状态并提示重试，拍一拍仅在服务端成功后提示送达，避免界面显示假成功。
- Feed 资产稳定性：Web 对 `p_demo_1` 至 `p_demo_4` 使用按照片 ID 的本地视觉资产映射；AI 合照或新上传内容改变排序后，刷新仍保持种子照片与正确素材对应。
- 删除失败反馈：照片删除通过统一异步动作包装器处理；存储或网络错误时保留 Feed 卡片并显示可重试提示，不产生未处理 Promise。
- 消息发送边界：服务端鉴权、存储或业务错误会保留输入草稿并提示重试，不再生成本地假消息；仅在浏览器真正无法连接 API 时允许 Demo 本地 fallback。
