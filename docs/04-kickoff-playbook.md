## 1. 分工总原则：你管横向，三人各管一条纵向

三条纵向互不直接对接，一切交界（契约/环境/验收/节奏）归你。**你看 demo，不看 diff；你审契约，不审实现。**

| 角色 | 纵向拥有 | 关键点 |
|------|----------|--------|
| **全栈（在身边）** | ECS/域名/备案执行、API、Postgres/OSS、web 实现、CI/备份/监控、mock server | 与你每天 15 分钟站会 |
| **硬件（remote）** | 固件（相机/滤镜/显示/网络/省电）、3D 外壳、烧录脚本、整机装配 | 摸不到你的设备 → 日志与 CI artifact 是他的眼睛 |
| **UI** | web 视觉（贴贴风）、**设备屏 UI 与按键交互**、滤镜视觉定义、品牌与内测物料 | 设备屏是最容易被漏掉的交付物 |

## 5. Remote 硬件协作协议（6 条，kickoff 上宣布）

1. **串口日志统一格式**：`[FW] METHOD PATH STATUS MS`，报 bug 必附日志 + fw 版本号。
2. **固件 PR → CI 构建 .bin artifact → 你在本地同款设备烧录复现**。他摸不着你的机器，你也摸不着他的——CI 产物是共同基准。
3. 每周一次视频 demo（或录屏），周会进行。
4. W2/W3 联调日：语音常开 + 屏幕共享，串口/服务端日志直接甩群。
5. **阻塞 24 小时不过夜**，对 remote 加倍执行；约定每日固定重叠时段（≥1 小时）。
6. 烧录产线脚本由硬件交付，**100 台烧录在你这边执行**（设备都在你手上）。

## 8. 反模式（六个）

1. 自己下场写后端——你的杠杆在接口/验收/疏通，手痒只写验收脚本。
2. 让硬件等后端——mock 永远先行。
3. 把第一次联调拖到 M2——W1 就真机握手。
4. 用"看看再说"当验收——demo 标准写死在日历邀请里。
5. **让 UI 隔空设计设备屏**——D1 必须拿到硬件物理规格，设备屏出 1x 像素稿，否则返工。
6. **让你手上那台同款设备闲置**——每个固件 PR 的 CI 产物都烧上去跑一遍，你就是 remote 协作的本地手臂。
