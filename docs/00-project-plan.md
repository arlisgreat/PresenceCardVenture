# 小卡 MVP · 项目总体规划 v1

> **一句话**：两条工作流（全栈=云端+web，硬件=固件+整机）靠"契约先行"解耦并行，
> 5 周到 100 人内测；**关键路径是 ICP 备案，第一周第一天必须提交**。
> 文档包：`01-cloud-architecture.md`（云端方案）、`02-device-api-v1.md`（设备 API 权威规范）、
> `03-device-api.openapi.yaml`（可导入调试的契约）。

---

## 1. 角色与分工

| 角色 | 拥有 | 不负责 |
|------|------|--------|
| **技术一号位（你，兼产品）** | 契约/环境/验收/节奏/风险；需求冻结；UI 调性裁决；**本地固件复现与烧录测试**（手上有同款硬件）；内测运营 | 不逐行 review 实现 |
| **全栈工程师（在身边）** | ECS/域名/备案执行、API、Postgres/OSS、web 实现、CI/备份/监控、mock server | 不碰固件 |
| **硬件工程师（remote）** | 固件（相机/滤镜/显示/网络/省电）、3D 外壳、烧录脚本、整机装配 | 不碰后端实现 |
| **UI 设计师** | web 视觉（贴贴风）、**设备屏 UI 与按键交互稿**、滤镜视觉定义、品牌与内测物料（包装卡/二维码/贴纸） | 不写生产代码 |

> v1.1：团队扩为 4 人（+UI）；硬件工程师 remote，协作协议见 04 §5；UI 交付节奏见 04 §6。

**协作原则——契约先行**：
`03-device-api.openapi.yaml` 是双方唯一接口契约。改契约 = 先提改契约的 PR，双方 review 通过后实现。
任何一方不允许"先改了再说"。规范文档（02）与契约不一致时，以 02 为准并立即修契约。

## 2. 关键路径：ICP 备案

```
W1 D1  提交备案（阿里云 App，主体资料：身份证/营业执照、域名证书、服务器）
W1–W3  管局审核（通常 3–20 个工作日，各省不同）——期间开发联调完全不受影响
W3–W4  备案通过 → 域名正式解析 api./app. → 内测上线
        （通过后 30 日内办公安联网备案，可上线后补）
```

- **备案期间联调方案**：ECS 公网 IP + 非标端口，或 frp/cloudflared 内网穿透；固件把 base URL 做成编译期配置，切换无成本。
- 若域名/服务器已有备案：本路径消失，整体提前 1–2 周。
- 备案主体建议用公司主体（若产品后续商业化）；个人主体也可，注意个人备案不能涉及经营。

## 3. 环境与域名规划

| 环境 | 地址 | 数据 | 用途 |
|------|------|------|------|
| mock | 全栈本地/ECS，`npx @stoplight/prism-cli mock 03-device-api.openapi.yaml` | 假数据 | **W1 D2 前给硬件**，固件零等待开工 |
| dev | `api-dev.域名`（备案前=IP+端口） | 真库真 OSS，每周清空 | 日常联调 |
| prod | `api.域名` / `app.域名` | 内测真实数据 | 100 用户 |

固件侧 base URL、配对码长度等全部编译期可配；dev/prod 两套固件构建目标。

## 4. 仓库与节奏

```
PresenceCardVenture/   ← monorepo（github.com/arlisgreat/PresenceCardVenture）
├── docs/              ← 本文档包 + 契约（契约的家）
├── server/api         ← Fastify+Prisma
```

- 主分支保护 + PR；服务器 push main 自动部署 dev，打 tag 部署 prod。
- **节奏**：每周一次三方站会（30 分钟，对里程碑）；W2/W3 末各一次集中联调日。
- 沟通群：一个群全在，联调日志（串口输出 HTTP 状态码）直接甩群里。

## 5. 五周计划

### W1 · 启动周（并行起跑）

| 全栈 | 硬件 | 产品 |
|------|------|------|
| ECS 初始化（docker/compose/Caddy）、CI、Postgres、开通 OSS | 开发环境（PlatformIO/IDF）、相机出 JPEG、屏幕刷屏 demo | **D1 提交 ICP 备案** |
| **M1**：pairing + 上传 + feed 三接口上 dev 环境 | 按键扫描、配网方案验证（AP/BluFi 双保险） | UI 调性定稿（贴贴风参考稿）、内测策略 |
| D2 起 Prism mock 可用 | 对着 mock 写 HTTP 客户端层 | 100 台外壳打印排产 |

**W1 验收（M1）**：curl 全流程脚本通过；**真机对 dev 环境完成 TLS 握手 + 一次上传**（这一步提前暴露证书链问题，是全项目最重要的早期验证）。

### W2 · 各自纵深

| 全栈 | 硬件 |
|------|------|
| 设备 API 全量（feed/reactions/state/friends）、幂等与限额 | 配网 + 配对联调通（显示配对码→拿到 token） |
| web：注册登录、加好友（friend_code）、绑定设备 | 拍照 → 滤镜 LUT → 上传链路（对 dev） |

**W2 末集成点**：真机拍一张照片 → web 时间线可见。

### W3 · 打通双向

| 全栈 | 硬件 |
|------|------|
| web：时间线、反应（❤️）、我的主页 | feed 拉取 → 好友照片解码刷屏、反应按键、本地缓存 8 张 |
| ETag/304、错误码核对（对照 02 §0 表） | 省电轮询（state→有更新才拉）、待传队列、断网补传 |

**W3 末集成点（M2）**：两台设备 + 两个账号互为好友，**A 拍照 → B 设备一个轮询周期内显示**；02 文档 §7 四条验收用例全过。

### W4 · 内测加固

| 全栈 | 硬件 | 产品 |
|------|------|------|
| 备份（pg_dump→OSS）、监控告警（钉钉 webhook）、日志 | 异常恢复（401 回配对、429 退避）、烧录产线脚本（批量 device_id） | 内测手册（配网/配对图文）、反馈群 |
| 极简管理（删图/封号/重置配对） | 外壳装配 10–20 台、老化测试（连续拍传 100 张） | 账号预注册方案（用户名+初始密码卡片随机器发） |

**W4 验收（M3）**：内测就绪评审——按 02 §6 checklist 逐项打勾 + 备份恢复演练一次。

### W5 · 内测

- 先发 10–20 台（同事/朋友）跑 3–5 天，集中修崩溃与配网失败。
- 修完放量到 100 台；**M4 = 稳定运行 2 周**（设备日均在线率、上传成功率 >98%、P95 上传耗时 <15s）。
- 冻结需求：评论/广场/离线传输一律记入 Phase 2+  backlog，本周不接新需求。

## 6. 内测运营要点

- **发机包**：小卡 + 卡片（初始账号密码 + 配网二维码 + 反馈群二维码）。
- **烧录产线**：`esptool` 脚本批量烧固件 + 逐台写入唯一 `device_id`，机身贴序列号；登记表（序列号 ↔ device_id ↔ 账号）。
- **反馈闭环**：群里接报 → 硬件要串口日志，全栈查服务端 trace；每周出一份故障 top3。
- **隐私告知**：好友闭环产品，页面上写明"仅你的好友可见"；提供删除照片与注销入口。

## 7. 风险登记

| 风险 | 概率/影响 | 对策 |
|------|-----------|------|
| ICP 备案延迟 | 中 / 高 | W1D1 提交；期间 IP+非标端口联调；极端情况临时 HK 节点过渡 |
| ESP32 与证书链/TLS 兼容 | 低 / 中 | **W1 真机握手验证**（M1 验收项）；用 Let's Encrypt（ISRG Root X1 在 esp_crt_bundle 内） |
| 家用/校园网配网失败 | 中 / 中 | AP + BluFi 双方案；固件记录配网失败码；内测首批重点观察 |
| 照片隐私泄露 | 低 / 高 | OSS 私有桶 + 预签名 10 分钟；删除权；好友闭环无公开页 |
| 单点运维（一台 ECS） | 中 / 中 | 每日备份 + 恢复演练；重启手册一页纸；磁盘告警 |
| 需求蔓延 | 高 / 中 | MVP 冻结清单；新需求只进 Phase 2+ backlog，由产品（你）守门 |
