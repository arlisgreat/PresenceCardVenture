# AI 小卡前后端 Demo 设计

**目标**：在不依赖真实 ESP32 硬件和外部 AI 账号的情况下，交付一套可操作、可测试的 AI 小卡社区 Demo。

## 设计边界

- Web 社区、业务 API、图片处理、AI 合照任务和设备模拟器全部可在本地运行。
- 设备对外接口继续使用 `/v1` 设备协议；Demo 不改变既有字段语义。
- 图片使用本地存储适配器，算法使用可替换的本地模拟实现；生产 OSS、真实模型和硬件联调留作后续适配。
- 内容权限、素材授权、删除和任务失败是 Demo 的真实业务逻辑，不用静态文案伪装。

## 用户主流程

1. 用户进入社区，使用预置 Demo 身份登录。
2. 用户在创作页选择图片、滤镜、美颜参数和贴纸/边框，提交后生成原图与处理结果。
3. 处理结果进入好友时间线，用户可以点赞、查看作者和删除自己的内容。
4. 用户在消息页选择好友发送文字或图片消息。
5. 用户选择两张已授权素材创建 AI 合照，查看排队、处理中、成功或失败状态。
6. 用户在设备模拟器中以设备身份上传照片、拉取动态、确认下发并回传回执。

## 架构

```text
React/Vite Web
      │ /v1 proxy
      ▼
Fastify API
      ├── Demo auth and permissions
      ├── Photo metadata and local file storage
      ├── Feed, reactions, friends and messages
      ├── AI job state machine (local adapter)
      └── Device protocol and simulator endpoints
```

API 内部以仓储和适配器隔离持久化、图片处理和 AI 生成。这样 Demo 可以使用进程内数据和本地文件，后续替换 PostgreSQL、OSS、FastAPI 或队列时不改变 Web 和设备契约。

## 数据与权限

- Demo 用户、好友、照片、消息、反应和 AI 任务使用进程内种子数据；图片文件写入 `server/api/uploads/`，该目录不提交 Git。
- 每张照片记录 `original` 或 `processed` 类型及其所有者；仅所有者能删除，时间线只返回自己或已接受好友的内容。
- AI 合照创建请求明确列出素材 ID；服务端验证当前用户拥有或已获授权的素材，结果继承参与者的可见范围。
- 所有删除接口返回确定性状态，前端在删除后同步移除卡片和详情。

## API 边界

- 保留设备契约：`POST /v1/photos`、`GET /v1/feed`、`GET /v1/device/state`、照片下载、反应和配对路径。
- 增加 Demo 社区接口：会话、好友、消息、滤镜处理和 AI 任务；接口返回统一 JSON 错误结构。
- 图片上传使用 `image/jpeg` 原始 body，支持浏览器 Blob 和 ESP32 定长请求；服务端限制 1MB，并校验宽高/幂等键。
- AI 任务为异步状态机：`queued → processing → completed|failed`；本地实现使用可控延迟和可重复的合成结果占位图。

## 页面结构

- **Feed**：时间线、可见范围、滤镜标签、点赞和删除。
- **Create**：图片选择、滤镜/美颜控制、贴纸/边框选择、处理预览和发布。
- **Messages**：好友列表、消息流、文字输入和图片发送。
- **AI Studio**：素材选择、授权状态、任务创建和状态卡片。
- **Device Lab**：设备身份、上传、拉取、下发和回执日志。

页面采用移动优先布局，使用清晰的操作状态、错误反馈和加载状态；不依赖外部图片 URL 才能展示核心流程。

## 测试与交付

- API：健康检查、上传限制、幂等、权限、删除、消息和 AI 状态转换测试。
- Web：构建测试和浏览器主流程验收，至少覆盖上传发布、点赞删除、消息发送、AI 任务和设备模拟。
- 交付：本地启动命令、Demo 账号、已知限制和接口示例写入文档；每个阶段独立提交，网络恢复后再同步远端。
