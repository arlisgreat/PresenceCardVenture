## 2. 状态机（页面与固件共用命名）

```
UNBOUND ──POST /pair/code──▶ PAIRING(显示 6 位配对码)
PAIRING ──轮询 /pair/status 202 pending…200 bound──▶ BOUND_FLASH(绑定成功, 1.2s)
BOUND_FLASH ──▶ IDLE(待机时钟, 零 UI 只剩时间戳)
IDLE ──unseen_count>0──▶ ARRIVE(拍立得飘入+昵称贴纸)
ARRIVE ──0.95s 后──▶ FULLSCREEN(铺满 800×480)
FULLSCREEN ──1.6s 后──▶ ZEROUI(贴纸/手写字淡出, 只剩照片)
ZEROUI ──GT911 按下──▶ STAR(涟漪→星星+粒子+气泡, 2.1s) ──▶ ZEROUI
ZEROUI ──下一张到达──▶ NEW_ARRIVE(新拍立得压上来, 旧照片留在底下)
ZEROUI ──t≥夜航阈值(演示用循环尾部)──▶ NIGHT(60% 遮罩, 时钟转夜间配色)
NIGHT ──下一张到达──▶ (抵亮) NEW_ARRIVE
```

固件备注：`IDLE` 对应现状的"每 10s 轮询 /device/state"；`NEW_ARRIVE` 即局限 5"新照片硬切"要替换成的动效。

## 3. 六幕节拍表（总时长 34.8s，一循环）

| t(s) | 节拍 | 画面事件 | 协议旁注（照 02-device-api-v1） | 占位曲线 | 固件移植要点 |
|------|------|---------|------------------------------|----------|--------------|
| 00.0 | **配对** | grass_green 面板铺底；标题"把相框连上你的小卡"；6 位配对码 **482913** 逐位弹入（accent_sky_blue 大字）；副文"在小卡的 web 社区输入这 6 位" | `POST /pair/code → {pair_code:"482913", expires_in:600}` | `cubic-bezier(.2,1.1,.3,1.3) · 0.45s` ×6 位 | 面板纯色刷整屏；数字即固件现有 CJK 字号放大 |
| 04.2 | **绑定成功** | 面板整屏闪切 dark_night 底；中央 candy_pink 对勾弹出 + "已绑定 · 阿岩的相框" + 轮询结果行 | 轮询 `GET /pair/status` 202…→200 | `cubic-bezier(.2,1.2,.3,1.35) · 0.6s` | 成功后整屏 fade（背光 PWM）切到待机 |
| 06.2 | **待机** | 面板退去；paper_white 底 + 09:31 时间戳（accent_sky_blue）+ candy_pink 呼吸点 | 每 10s `GET /device/state`，`unseen_count` 门控 | 呼吸 `ease-in-out · 2.2s` 循环 | 待机是固件现状，零新增工作 |
| 09.0 | **照片飘入** | 拍立得从右上飘落、过冲两次停在 -2°；lilac 贴纸 03.4 式弹出；手写字题注 | `GET /feed` → 下载 JPEG → 解码 | 飘入 `cubic-bezier(.22,.9,.28,1.12) · 1.05s`；贴纸 `(.2,1.1,.3,1.25) · 0.7s` | 新图到位前先压黑（PWM 渐暗），避免半解码帧露出 |
| 13.0 | **铺满全屏** | 白框收进边缘，照片铺满 800×480 → 1.6s 后贴纸/题注淡出（零 UI） | — | `cubic-bezier(.35,0,.15,1) · 0.95s`；淡出 linear 0.8s | 全屏化=裁剪重排，RGB565 直驱不做 alpha 混合 |
| 17.0 | **点星星** | GT911 触点涟漪（candy_pink，触摸反馈本体）→ cream 星星弹出 + 6 粒子 + "★ 阿岩 点了星星"气泡 → 2.1s 后整体淡出 | `POST /photos/{id}/reactions {type:"heart"}` | 涟漪 ease-out 0.75s；星星 `(.2,.9,.3,1.4) · 0.85s` | 触摸按下即画涟漪，不等服务器回包；失败静默重试 |
| 22.4 | **下一张压上来** | 新拍立得（第二张）以同样飘入动效压在旧照片正上方 → 再次铺满全屏 → 零 UI | feed 第二页/下轮轮询 | 同"照片飘入" | 旧图保留在帧缓冲底层，新图在其上动画，无需双缓冲全清 |
| 30.0 | **夜间** | dark_night 60% 遮罩压上照片，底部浮出夜间时钟（转夜间配色） | 定时策略：本地 22:00–07:00（演示取循环尾部） | 遮罩 linear 0.6s | 遮罩=背光 PWM 降到 40%，LCD 不重绘，最省电 |
| 34.8 | 循环 | 回到配对幕（演示用；真机不回到配对，只循环 待机→照片→夜间） | — | — | — |

录屏指南：**完整故事录 00.0–34.8s 一整圈**；只要"相框日常"则录 06.2–34.8s。
URL 控制：`#t=13300` 从该时刻播；`#t=13300,freeze` 慢放定格（瞬时动画 20 倍慢放，
录屏/截帧时涟漪、粒子、对勾可见）；`#t=13300,hardfreeze` 硬冻结（所有动画与过渡
暂停在该帧，设计审查/截图用，确定性、无采样窗口问题）。

> 实现备注：瞬时动画（涟漪 0.75s、粒子 0.95s、对勾 0.6s）比 headless 截图的
> 采样窗口短，普通定格截不到它们——v2 第一轮审查就栽在这。slowmo/hardfreeze
> 两种定格就是为这个坑准备的；验证瞬时层时必须用它们之一。

## 5. 双拍立得机制（轮播节拍的实现约束）

拍立得的状态类（arrived/settled/stickered/fullscreen/zeroui）**挂在拍立得元素自身**，
不再挂 stage——否则第二张飘入会连带第一张重播。stage 只挂全局状态
（idle/pairing/night）。轮播时新拍立得绝对定位插入旧照片层之上，
全屏化后旧拍立得被完全遮住，可在下一循环回收 DOM。

### 验证轮次记录

- 第 1 轮（noanim 定格）：9 帧截图 + 三路并行审查，抓到 3 个真缺陷——
  ①绑定成功层 okin 动画卡 opacity 0 且配对内容半退场（改：对勾层改纯状态类 +
  数字/轮询行加 boundflash 退场规则 + 面板回归 pairing 再淡出）；
  ②第二张全屏后贴纸/题注未淡出（slowmo 补过渡覆盖）；
  ③点星星瞬时层（触点/涟漪/粒子/光晕）定格不可见（引入定格模式 + 星星组左移）。
- 第 2 轮（slowmo 慢放定格）：瞬时层可见了，但慢放引入采样窗口回归
  （贴纸半透明、拍立得全屏过渡中途、绑定成功层 20s 淡入只走了 15%）。
- 第 3 轮（hardfreeze 硬冻结）：发现 headless 虚拟时间下 `transition:none` 的坑——
  类应用瞬间样式重算会**取消运行中的过渡并立即跳到目标值**，而目标值
  （如 zeroui 的 opacity:0）本应到时刻 t 才生效，导致对勾层停在 base opacity 0、
  贴纸/题注在 zeroui 帧关不掉。**最终方案：`transition-delay:100000s` 让过渡
  挂着不走，元素保持类应用前的样式；动画直接 `animation:none` + 瞬时层强制终态。**
  这是可复用的 headless 动效定格方法，已写进页面注释。
- 第 4 轮（终审）：9 帧 hardfreeze 重截 + 三路并行复审。
- 第 5 轮（noanim 保留 + 全场景终态钉死）：实测发现前两轮记录的判断不完整——
  `.noanim` **移除**瞬间，被压住的过渡从旧值起跑、CSS 动画复活，headless 捕获
  的是起跑帧：配对帧数字缺失、绑定帧对勾空白、待机帧面板不褪、全屏帧贴纸重出
  全由此而来。最终定稿的定格模型：**hard 模式下 `.noanim` 全程保留**，元素终态
  由 hardfreeze 规则按类组合钉死（状态层 opacity + 动画层 transform/opacity）。
  同时把绑定成功幕从"面板上叠对勾"重设计为**整屏闪切 dark_night 底 + 对勾**——
  面板上叠层需要 panel/boundok 同步透明度过渡，正是定格模式的死穴；整屏替换后
  该幕只剩一层状态，live 与 freeze 行为天然一致。9 帧重截全部通过。
