# 交互与视觉资产迭代

## 这一轮的设计决定

Presence 的互动不做喧闹的社交动效，而是把“在场”变成轻微但可感知的反馈：双击照片会出现短暂心动回响，拍一拍作为独立的轻信号写入 API，上传区支持拖入照片并即时预览，AI 合照显示素材选择进度，设备实验室用短暂同步态模拟真实联调。

## 视觉资产策略

当前终端没有可用的 `OPENAI_API_KEY`，本轮不把未验证的模型输出写进仓库。为避免网络波动，已将三张可替换的演示照片缓存到项目本地；模板和边框保持代码化参数，后续拿到 Image 2 凭据后再生成并替换以下资产：

- 本地演示照片：`feed-window.jpg`、`feed-portrait.jpg`、`feed-friends.jpg`
- 4 张 4:5 圈子种子照片：傍晚窗台、宿舍夜灯、朋友合照、胶片街景
- 2 张拍立得边框：纸白窄边和淡粉手账边
- 2 组贴纸：星星轻回应和日期戳

资产进入 `server/web/public/assets/`，由 `api.ts` 的素材适配器引用；不把远程临时 URL 当作生产资源。当前照片是本地化演示缓存，正式发布前应替换为团队自有或已授权素材。

## 验收重点

- 互动反馈不改变布局，不阻塞下一步操作，并尊重 `prefers-reduced-motion`。
- 拖拽上传与点击选择走同一条文件校验和发布路径。
- Web 端 PNG 在浏览器内压缩转换为 JPEG，再复用设备端 `POST /v1/photos` 契约。
- AI 任务的选择、排队、处理中、成功和失败状态都有明确视觉反馈。
- 设备模拟按钮在动作执行期间有忙碌态，日志顺序与请求语义一致。
