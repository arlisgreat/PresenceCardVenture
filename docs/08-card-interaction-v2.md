# 小卡交互设计 v2 —— 基于设备真实能力的重设计

> 2026-08-30 · 硬件端提案。v1.1 总文档 §1-§3 的手势/模式设计在 2 寸屏上不成立，
> 本文档给出替代方案。§4 闪现、§5 拍照主流程、§8 Design Tokens 继续沿用。

## 0. 为什么要重设计

v1.1 的交互是"桌面端思维"：7 种手势、三模式选择盘、90×36px 的按钮。
但设备的物理现实是：

| 硬件事实 | 设计约束 |
|---|---|
| 2.0" 320×240 屏，~220ppi | 指尖接触面 ≈ 60-80px，**任何点击目标 ≥ 64px**；v1.1 的 90×36 按钮按不准 |
| FT6336 单点电容触摸 | 无双指手势；手势种类越多误判越多 |
| 挂在身上/单手拇指操作 | 常常不看屏幕盲操作；误触必须无害 |
| ESP32-S3 240MHz + LVGL 软渲染 | 全屏 per-frame alpha 混合动画吃不消；动效只做小对象的位移/透明度/缩放 |
| AW88298 喇叭（已有快门/到达/点赞音） | **声音是免费的反馈通道**，比动画便宜一个数量级 |
| hw2d SIMD 滤镜管线（已有） | 滤镜实时切换零成本，取景器体验可以做满 |

三条设计原则（按优先级）：**① 简洁 ② 符合人性 ③ 观众看着有意思**。

## 1. 手势语言：7 种砍到 4 种

心智模型一句话：**"点一下是喜欢，按住是留住，左右是翻，上下是抽屉。"**

| 手势 | 看照片时 | 拍照时 | 人性依据 |
|---|---|---|---|
| **Tap** | ⭐ 星星 + like（连击不限） | **快门（全屏都是快门键）** | 误触无害化：最容易发生的手势对应最无害最愉悦的动作 |
| **左右滑** | 翻上/下一张 | 切滤镜（实时变色） | 翻页是全人类的肌肉记忆 |
| **下滑 / 上滑** | 下滑=拉下相机；上滑=拉出系统抽屉 | 上滑=收起相机回看照片 | "相机是从上面拉下来的快门帘"，推回去就收起，进出对称 |
| **长按 ≥1.2s** | **钉住/松开当前照片**（替代三模式盘） | — | "按住 = 留住这张"，比呼出选择盘再选卡片少两步 |

被砍掉的东西及理由：
- **三模式选择盘（v1.1 §3）**：整个删掉。"常驻模式" = 长按钉住（钉住时流停在这张，
  角上贴一条和纸胶带作为状态提示）；松开回到小圈流。零 UI、零状态盘、零教学成本。
- **大圈模式**：从卡端 UI 删除（本来就是 P2 画饼），App 端订阅后大圈照片直接混入流即可。
- **手势阈值窗口 <400ms**：删掉时间窗，只按位移判定（ΔX/ΔY > 48px，约 1/5 屏宽）。
  慢慢滑也算滑，对老人小孩友好；时间窗只保留连击间隔 300ms 一处。

## 2. 屏幕即按钮：三个界面，每屏只有一件主事

### 2.1 看照片（默认态 = 小圈流）
- 全屏照片慢速轮播（30s/张）；附言用拍立得下巴（沿用 v1.1 §4.2）。
- 点按任意处 = ⭐ + `PVC_SND_LIKE`（连击音调逐击升高——纯音效变化，零渲染成本）。
- 连击 ≥5 次触发"星星雨"：一次性 12 颗粒子 + 徽章 `+N`，粒子上限 12，40ms 帧步。
- 长按 1.2s：`咔哒`一声，和纸胶带斜贴到照片角上（一张 64×24 预渲染贴图旋转 -8° 滑入）= 钉住。
  再长按：胶带撕下来（反向动画 + 音效）= 回到流。

### 2.2 拍照（下滑进入）
- **全屏就是快门**。底部只画一条细白线提示"点哪都能拍"。
  砍掉 Ø44 圆钮——在 2 寸屏上让用户瞄准 44px 是折磨。
- 快门反馈三连：白闪 1 帧（纯色矩形，零成本）+ `PVC_SND_SHUTTER` + 定格。
- 左右滑切滤镜（已实现，实时 LUT），顶部滤镜名条沿用。
- **定格预览：左右对半分两个大按钮**（各 160×48px）：`✕ 重拍` ｜ `↑ 发出去`。
  拇指闭眼都按得中。v1.1 的"按住录音"降为 P1：按住右钮说话，松手即发。
- 发布动效：照片缩小飞向屏幕顶端消失 + `PVC_SND_DING`——
  紧接着**对端相框亮起到达仪式**，这是全场 demo 的 money shot，卡端动画越短越好（600ms）。

### 2.3 系统抽屉（上滑进入）
- 从底部升起半屏抽屉：Wi-Fi/电量状态行 + 两个大按钮：`💖 设为常驻`（=钉住的另一入口，
  给不知道长按的人）+ `🌙 息屏`。换肤、删除降为 P1。下滑或点上半屏收起。

### 2.4 闪现（全局优先，沿用 v1.1 §4.1 骨架）
- 好友新照片：`PVC_SND_DING` → 500ms 淡入（预混合暗帧，不做 per-frame 全屏 alpha）→
  停留改为 **12s 或任意触摸提前结束**（20s 在 demo 现场太长，观众注意力 8 秒）。
- 停留期间点按 = 直接给这张发星星——到达和回应在同一拍完成，这就是产品叙事。

## 3. 声音优先的反馈预算

动画在 320×240 软渲染上是稀缺资源，声音不是。反馈分配：

| 事件 | 声音（主反馈） | 动画（辅助，全部 ≤600ms 小对象） |
|---|---|---|
| 点赞 | 上扬滑音，连击升调 | 单颗星 12→20px 上飘 |
| 快门 | 咔嚓 | 1 帧白闪 |
| 发布 | ding | 照片缩飞 |
| 到达 | 双音下落 | 淡入 + 名字贴纸滑入 |
| 钉住/松开 | 咔哒 / 撕纸 | 胶带贴入/撕出 |

## 4. 性能红线（实现时不许越）

1. 禁止全屏 per-frame alpha 动画；压暗用预混合帧一次性生成。
2. 粒子 ≤12 颗，每颗只做位移+透明度；LVGL anim 只挂 transform/opacity。
3. feed JPEG 解码走已有 worker 队列，UI 线程零解码。
4. 手势判定在 touch 中断的采样点上做纯算术，无定时器轮询。
5. 音效播放非阻塞（pvc_sound 已满足）。

## 5. 与相框端的语言一致性

相框端已实现并验证：tap=星星+like、长按=模式选择盘、左右滑=翻页——与本方案 4/5 同构。
黑客松期间相框保持现状（已验收）；赛后若采纳本方案，相框的三模式盘同样可降级为
"长按钉住"，两端心智模型完全统一。

## 6. Demo 剧本对照（P0）

1. 观众点卡片 → 星星连击 + 升调音效（3 秒内让观众笑出来）
2. 下滑 → 全屏快门拍观众 → 左右滑变滤镜 → 大拇指按"发出去"
3. 两秒后相框响 ding、晚霞仪式浮现 → 观众在相框上连点出星星雨
4. 长按卡片钉住 → 和纸胶带贴上（呼应相框的拍立得视觉语言）

—— 每一步一个手势、一个声音、一个动效，没有任何一步需要解释。
